本书大部分内容都以对话为前提：你写一个提示词，AI 给出回答，你停下来时会话就结束了。正如前几章所展示的，智能体在一次会话中可以做更多事情。但当你关闭窗口时，工作通常也随之停止。

**常驻机器人**会继续工作。它有长期的身份和角色、工作的地方、能跨对话保留的记忆，以及无需你发起就能开始的工作。你交给它的是一份职责，而不是单个任务。

本章把常驻机器人作为一个概念来讲解。我们用三个产品作为例子：**Grok Bot**，一款托管产品，在云电脑上运行有名字的 Bot；Nous Research 推出的 **Hermes Agent**，可以在你自己的电脑或服务器上运行；以及 **OpenClaw**，一个自托管的网关，把智能体连接到你的聊天应用。它们的设计选择各不相同，这些差异有助于解释其中的概念。

<Callout type="info" title="这些是示例，不是推荐">
产品细节变化很快。这里的描述以撰写本文时各项目的公开文档为准。依赖某项具体功能或限制之前，请先查看最新文档。
</Callout>

## 机器人的电脑

一个持续工作的机器人需要一个工作的地方。三个例子对这个问题给出了不同的答案。

**托管的云电脑。** Grok Bot 在一台常驻的云电脑上运行你的 Bot，这台电脑带有浏览器、命令行和文件。关闭应用或笔记本电脑不会停止云端的工作。你账户中的所有 Bot 共用同一台电脑：浏览器会话、文件和命令行凭据对它们全部可用。每个 Bot 有自己的屏幕，但文档说明这些屏幕是“独立的工作界面，而不是独立的安全边界”。不同用户之间，每台电脑都是专用的，并在硬件层面隔离（[Use the computer and apps](https://docs.x.ai/grok-bot/computer-and-apps)）。

**你自己运行的机器。** Hermes Agent 可以在你控制的机器上运行。它的终端工具可以在本机工作，也可以通过其他后端工作，包括 Docker、SSH，以及 Modal 和 Daytona 等云沙箱。对于匹配其危险模式列表的命令，Hermes 会在执行前请求批准。在容器后端中，这些检查会被跳过，因为容器本身被视为安全边界（[Hermes security](https://hermes-agent.nousresearch.com/docs/user-guide/security)）。OpenClaw 在你的主机上运行一个 Gateway，默认把智能体的工作区放在 `~/.openclaw/workspace`。它的沙箱默认关闭；启用后，工具执行会移到容器中，而 Gateway 仍留在主机上（[OpenClaw sandboxing](https://docs.openclaw.ai/gateway/sandboxing)）。

**你自己的电脑，需经许可。** 机器人的电脑和你面前的电脑是两回事。只有在该功能启用并获得批准后，Grok Bot 才会在你的本地机器上运行命令。默认设置是 *Ask every time*（每次询问），文档建议选择 *Never allow*（永不允许），除非某个 Bot 有明确理由处理你的本地文件。

有两个观点适用于所有这些配置。第一，**共享状态就是共享访问权限**：如果几个机器人共用浏览器、文件或凭据，它们中的任何一个都可能使用这些资源。第二，**隔离是一种决定**：OpenClaw 每个网关只支持一个信任边界，也就是单个操作者，或成员彼此信任的团队；对其他所有人，它建议使用独立的网关和凭据（[OpenClaw security](https://docs.openclaw.ai/gateway/security)）。

## 记忆：机器人应该记住什么

记忆让机器人无需重读每一段过去的对话，就能长期保持自己的角色。它应该保存**持久的事实**：你的偏好、机器人的职责、项目惯例和经验教训。它不应取代**权威来源**：保存当前事实的 CRM、日历、工单系统或财务系统。

每个例子实现记忆的方式不同：

- **OpenClaw** 把记忆写成智能体工作区中的普通 Markdown 文件。它的文档说得很直接：“模型只记得保存到磁盘上的内容。”`USER.md` 保存稳定的偏好，`MEMORY.md` 保存持久的事实和决定；两者都在会话开始时加载。`memory/YYYY-MM-DD.md` 中的每日笔记记录持续的观察，以后可以搜索。一个名为 *dreaming*（做梦）的后台过程会把其中有用的内容提升到 `MEMORY.md` 中（[OpenClaw memory](https://docs.openclaw.ai/concepts/memory)）。
- **Hermes Agent** 维护两个小文件：`MEMORY.md` 记录智能体对其环境和惯例的笔记，`USER.md` 记录你的偏好。两者都有字符数限制，因此记忆会保持精选。它们在会话开始时作为冻结的快照加载，所以会话中保存的事实会出现在下一次会话里。对于更早的细节，智能体可以搜索过去的对话（[Hermes memory](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)）。
- **Grok Bot** 让每个 Bot 保留稳定的工作偏好、重要事实和工作摘要。它的文档提醒：“记忆不能替代权威来源。”文档建议把会变化的事实保存在源系统中，并在做重要决定时让 Bot 重新打开当前数据（[Create and manage Bots](https://docs.x.ai/grok-bot/bots)）。

<Compare
  before={{ label: "会过时的事实", content: "记住：Acme 的续约金额是 42,000 美元，3 月 3 日成交。" }}
  after={{ label: "指向来源的持久事实", content: "记住：Acme 续约由我负责。它的价格和成交日期保存在 CRM 的商机记录里。引用其中任何一项之前，先重新打开 CRM；如果和你上次的摘要相比有变化，请告诉我。" }}
/>

有些记忆会影响机器人以后应该做什么。对于这类*与操作相关的记忆*，OpenClaw 建议记录何时可以安全执行、笔记何时过期，以及谁拥有决定权。它也把限制说得很清楚：“记忆可以保留批准的上下文，但它不会强制执行策略。”

<Callout type="tip" title="记忆是提示词的一部分">
保存的记忆会被加载到以后的上下文中，所以一条错误的记忆可能影响之后的每次会话。检查机器人保存了什么，纠正过时的条目，并谨慎对待由不可信内容生成的记忆。Hermes 会在接受记忆条目之前扫描其中的提示词注入和凭据外泄模式，因为这些条目会被注入系统提示词。
</Callout>

## 从技能到例行任务

常驻机器人最有用的工作，是你已经做过一次的工作。Grok Bot 的文档建议了清晰的顺序：先做一次性任务，让它变得可靠，把方法保存为技能，然后才把它自动化（[Skills and routines](https://docs.x.ai/grok-bot/skills-routines-and-automations)）。

**技能**描述*如何*完成工作。**例行任务**描述某个特定机器人*何时*去做。Hermes 也采用同样的划分：定时任务可以附加一个或多个技能，它的提示词则成为叠加在这些技能之上的任务指令（[Hermes cron](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron)）。OpenClaw 把*常设指令*（standing orders）和*自动化*（automations）分开：前者在 `AGENTS.md` 中定义一个工作项目的权限、触发条件、批准关卡和升级规则，后者决定工作何时运行（[Standing orders](https://docs.openclaw.ai/automation/standing-orders)）。

### 例行任务必须说明什么

例行任务在你不在场、无法回答问题时运行。Hermes 对定时任务说得很直接：每次运行都在一个没有之前聊天记录的全新会话中开始，所以提示词必须自成一体，不能提出澄清问题。保存的记忆仍然会加载（[Cron internals](https://hermes-agent.nousresearch.com/docs/developer-guide/cron-internals)）。

### 定期检查和定时任务

例行任务大致有两种形式。**定期检查**定时唤醒机器人四处看看：有没有被卡住、紧急或新的事情？通常正确的做法是保持安静。**定时任务**在确切的时间运行一项具体任务，比如早上 9:00 的报告。

OpenClaw 展示了这两种模式。早期版本有单独的 *heartbeat*（心跳）用于定期检查，并配有 `HEARTBEAT.md` 清单。当前文档把心跳迁移成了普通的自动化任务。首次设置会创建一个 *Proactive check*（主动检查），默认每 30 分钟在智能体的主对话中运行一次。它会等智能体空闲时才运行，没有需要处理的事情时回复 `NO_REPLY`（[Heartbeat](https://docs.openclaw.ai/heartbeat/)）。对于精确的时间，比如每天 9 点整的报告，文档建议使用有独立定时计划的自动化（[Automation guide](https://docs.openclaw.ai/automation/cron-vs-heartbeat)）。

<Collapsible title="示例：OpenClaw 常设指令加一个自动化">

`AGENTS.md` 中的常设指令定义了这个工作项目。以下摘录改编自 OpenClaw 的文档：

```markdown
## 工作项目：每周状态报告

**权限：** 汇总数据，生成报告，交付给相关方
**触发条件：** 每周五下午 4 点（通过自动化任务执行）
**批准关卡：** 标准报告无需批准。异常情况标记出来交给人工审查。
**升级：** 数据源不可用或指标看起来异常时

### 不要做的事

- 不要把报告发送给外部人员
- 不要修改源数据
- 即使指标不好看也不要跳过交付——如实报告
```

自动化设置时间和时区。它的消息引用常设指令，而不是复制其内容：

```bash
openclaw automations add \
  --name weekly-status-report \
  --cron "0 16 * * 5" \
  --tz America/New_York \
  --message "按照常设指令执行每周状态报告。"
```

</Collapsible>

例行任务也可以由**事件**启动。Grok Bot 可以由 Slack 消息或 GitHub 通知等事件启动例行任务。Hermes 可以通过 webhook 触发定时任务，OpenClaw 支持经过身份验证的 webhook 和生命周期钩子。事件规则要尽量窄。Grok Bot 的文档提醒，“每条新消息”这类宽泛的监听器会制造噪音、消耗用量，并增加根据无关输入采取行动的可能性。

设置定时之前先测试。测试运行会做真实的工作：它可以浏览网站、修改文件、调用已连接的工具。使用安全的输入，并检查运行是否在批准边界处停下。

## 通过演示来教

有些工作流程演示起来比描述起来更容易，尤其是在没有清晰 API 的网站上。常驻机器人越来越多地支持你通过示例来教它。

在可用的地区，Grok Bot 提供 *Teach a task*（教一个任务）流程。你打开 Bot 的电脑，描述想要的结果，然后把工作流程完整操作一遍。Bot 会录制最长十分钟的可见电脑操作（不录制麦克风音频），并把它转化为一个技能。文档把这个技能称为**草稿**：你应该补充“仅凭一个例子可能看不出来的”决策规则、失败处理和批准边界，然后在设置定时之前用一个安全的例子测试它。Hermes 有一个 `/learn` 命令，可以把粘贴的流程、文档链接，或“你刚才在这次对话中带着智能体走过的工作流程”转化为保存的技能（[Hermes skills](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)）。

一次演示只展示一条路径。它不会说明遇到缺失的收据、重复的记录，或外观不同的页面时你会怎么做。演示之后，问问机器人它推断出了什么，又有哪些是它不知道的。

<TryIt compact prompt={`我刚刚向你演示了如何\${workflow:根据收件箱里的一张收据提交费用报销单}。请把它整理成一个技能草稿，但先不要保存或设置定时。

1. 按顺序列出你观察到的步骤。
2. 列出你推断出的决策，并标明哪些是你猜测的。
3. 就这个例子没有覆盖的情况向我提问，比如数据缺失、重复或出错。
4. 建议哪些操作应该需要我的批准。
5. 说明你将如何验证一次运行是否成功。`} />

演示时不要展示机密信息。Grok Bot 的文档建议改用它的安全交接流程来处理凭据。

## 委派和多个机器人

随着职责增加，一个机器人常常会变成几个。常见的模式有两种。

  { label: "队友机器人", description: "长期存在、角色、记忆和例行任务各自独立的机器人。它们互相发消息，并交接工作。", color: "green" }
]} />

Hermes 通过 `delegate_task` 工具提供子智能体。每个子智能体都有自己的对话、终端会话和工具集，只有它的最终摘要会返回（[Hermes tools reference](https://hermes-agent.nousresearch.com/docs/reference/tools-reference)）。OpenClaw 可以生成子智能体会话。它的安全指南建议，除非智能体确实需要，否则拒绝这项能力；对于必须保持在沙箱中的委派工作，要求使用沙箱（[Tool and agent permissions](https://docs.openclaw.ai/gateway/security/tool-permissions)）。

Grok Bot 更偏向队友模式。它的发布文章介绍了人们并行运行多个 Bot 的做法，有时还会用一个 *chief of staff*（幕僚长）Bot 来协调各个专业 Bot。Bot 之间可以互相发消息，并在群聊中协作（[Introducing Grok Bot](https://x.ai/news/introducing-grok-bot)）。它的设计文章解释了一条边界：工具和技能在账户层面共享，而记忆和例行任务属于每个 Bot。能力可以广泛共享，但上下文留在需要它的角色那里。

好的交接就是一个小提示词。它需要目标、输入、完成的标准和限制：

<Compare
  before={{ label: "含糊的交接", content: "嘿，你能处理一下结账的 bug 吗？" }}
  after={{ label: "另一个机器人能完成的交接", content: "在预发布环境中复现工单 BUG-412 里的结账崩溃。把步骤、浏览器和控制台错误记录到工单中。不要修改代码或生产环境设置。完成后，在这个讨论串里回复复现步骤，并说明崩溃是否每次都会发生。" }}
/>

分开角色有助于专注，但不能带来安全。Grok Bot 的文档说，不要把不同的 Bot 当作安全边界。OpenClaw 指出，智能体之间的消息默认开启，可以加以限制。如果两类工作需要不同的访问权限，就给它们不同的环境或凭据。

## 安全和批准

常驻机器人会在你没有看着的时候采取行动。这让它的边界比在聊天中更加重要。

**对外的操作需要批准。** Grok Bot 的文档列出了值得设置明确边界的操作：发送消息或邀请、发布内容、购买、删除或覆盖数据、更改权限、修改生产环境，以及接受法律条款（[Approvals, security, and privacy](https://docs.x.ai/grok-bot/approvals-security-and-privacy)）。一个好的默认做法是：让机器人起草、核对和提出建议，在任何事情脱离你的控制之前先询问你。

**无人值守的工作需要为批准做好计划。** 可能没有人能实时批准。在 Grok Bot 中，由不需要你发起的工作（比如例行任务）产生的批准请求，大约 10 分钟后就会过期，操作不会执行。在 Hermes 中，定时任务的默认做法是拒绝危险命令；智能体必须另找办法。这两种选择都是失败时默认关闭。设计例行任务时，要让等待或被拒绝成为安全的结果。

**机器人读取的所有内容都可能携带指令。** 提示词注入不需要陌生人出现在你的消息里。OpenClaw 的指南指出，机器人读取的任何不可信内容，比如网页、电子邮件、文档或附件，都可能包含恶意指令。一种缓解办法是使用只读的阅读智能体，为主智能体总结不可信内容。即便如此，这份摘要仍然是不可信的（[OpenClaw prompt injection](https://docs.openclaw.ai/gateway/security/prompt-injection)）。

**规则应该放在控制机制里，而不只放在记忆中。** “未经询问绝不给客户发邮件”是一条好的记忆。能拦下每一封外发邮件的批准规则，才是强制执行的控制。Grok Bot 建议“用批准和 Auto-review 规则，而不是只靠记忆”来保障安全边界。两者都要用：记忆说明意图，控制负责执行。

## 给常驻机器人写提示词

给常驻机器人写提示词，更像是写一份岗位职责说明，而不是提一个问题。例行任务会在你不在场时运行很多次。指令中的每一处空白，都会变成机器人独自做出的决定。

  before={{ label: "会逐渐偏离的例行任务", content: "每天早上检查我的收件箱，处理所有重要的事情。" }}
  after={{ label: "边界清晰的例行任务", content: "每个工作日早上 8:00（America/Chicago），查看 Clients 标签中过去 24 小时内的未读邮件。在这个聊天中发布摘要：每封邮件的发件人、请求、截止时间和建议回复。起草回复，但绝不发送。如果邮箱不可用，说明情况并停止。不要使用更早的数据。" }}
